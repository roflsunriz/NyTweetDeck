# NyTweetDeck Android機能パリティ受入基準

## 1. 目的と適用範囲

本書は、NyTweetDeck（NyTD）の現行コード、テスト、利用者向け文書で成立している機能をAndroid版へ移植した際の受入基準である。Android版の採点対象は「同じ操作で同じ利用者成果を得られること」であり、Web/desktop実装のクラス名や画面をそのまま再現することではない。

現行NyTDの基準値は、9種のカラム、6種の既定メニュー、10種の追加メニュー、11ロケール、3テーマ、3返信並び順、表示・メディア設定、X Web認証、X Web API、Live Pipeline、設定移送・復旧を含む。根拠は `README.md`、`docs/architecture.md`、`AGENTS.md`、`frontend/src`、`src/main/java`、`src/test` および `frontend/src` 内のテストである。

desktop固有の仕組みは、利用者成果を保ったまま次のように置換する。

- 専用Chrome/CDPによるログイン → Android上のX公式Webログイン導線。アプリ独自のパスワード入力は追加しない。
- 64pxの左レール → スマートフォンでは常時到達可能なドロワー/ボトム導線、横画面・タブレットではレールまたは同等の常時到達可能な導線。
- HTMLのドラッグ&ドロップ → 長押し開始のタッチドラッグ。
- `window.open` → Android Custom Tabまたは標準ブラウザ。
- EventSource/SSE → Androidで再接続、ライフサイクル停止、復帰同期が可能なストリーム実装。
- loopback、hosts、専用CA、自動起動、JDK/Bunのdesktop配布手順 → Androidのアプリ起動、アプリ内通信、アプリ更新へ置換。ただし、X通信、保存、認証境界、エラー処理、復旧は省略しない。

## 2. 採点方法と共通ゲート

各項目は全サブ条件を満たしたときだけ合格とし、未実装・未自動化・未実機確認はその項目を0%とする。合格率は項目の重みの合計で計算し、100%を受入完了とする。

実Xアカウントを使う検証は、事前に選んだ検証アカウントと副作用を許可したテストデータに限定する。CIや自動テストでは、認証情報を含まない採取済みfixture、fake repository、HTTPスタブを使う。テストログ、画面録画、スクリーンショット、共有設定JSONにはCookie、token、パスワード、個人情報、端末シリアルを出力しない。

自動テストは最低限、次の4層を揃える。

- 単体/契約テスト: NyTDの正規化モデル、ID検証、cursor、版移行、retry、rate-limit、重複排除、optimistic状態遷移を再現する。
- Compose UIテスト: 実際の画面導線で、タップ、長押し、ドラッグ、入力、開閉、キャンセル、戻る、エラー、再試行、永続化を確認する。文言ではなく安定したsemantic identifierを使う。
- 統合テスト: 認証済みAPI、GraphQL/REST、Liveイベント、設定保存をfake serverまたはMockWebServer相当で接続し、HTTPエラー・中断・再接続を確認する。
- AQUOS実機確認: 画面寸法、タッチ、ジェスチャー、キーボード、戻る、画面回転、バックグラウンド復帰、ネットワーク、見た目、操作感、TalkBackを確認する。

## 4. 機能別受入基準

### A-01 起動、初期状態、ログイン要求（2%）

- 観測可能な完了条件: 初回起動でクラッシュせず、保存カラムがなければ空のデッキとカラム追加導線を表示する。アカウント未選択時は、ポスト取得を開始せずログイン/アカウント選択が必要であることと次の操作を表示する。保存済みレイアウトがある場合は、起動後に復元処理を開始する。
- 自動テスト観点: cold start、force-stop後の再起動、空設定、APIが空アカウントを返す場合、初期設定ロード失敗と再試行をCompose UI/Repositoryテストで確認する。`frontend/src/app.test.tsx` と `frontend/src/model/use-shared-layout.test.tsx` の初期化・再試行ケースを移植する。
- AQUOS実機確認観点: SHARP `SH-R80P`（Android 16 / API 36、1260x2730 px、480 dpi）で初回起動、再起動、画面回転、戻る、アプリ切替からの復帰を行い、空状態・エラー・ボタンがステータスバー/ナビゲーションバーに隠れないことを確認する。

### A-02 X公式認証、セッション保持、複数アカウント（7%）

- 観測可能な完了条件: X公式ログイン画面で認証を完了し、アプリへ戻ると保存済みアカウントの表示名/ユーザー名が現れる。アプリ独自のパスワード入力欄に認証情報を入力させない。2アカウント以上を保存して切り替えられ、再起動後は前回選択を優先し、前回アカウントが利用不能なら保存一覧の#1を自動選択してカラム取得まで始める。ログイン中断、Web画面終了、認証失敗、ネットワーク断では再試行可能な状態になる。
- 自動テスト観点: 公式Web認証からの成功/キャンセル/期限切れ/中断、セッション取り込み、アカウント重複置換、保存一覧、前回選択・#1フォールバックをfake Web認証とRepositoryテストで確認する。資格情報をUI状態、ログ、設定JSON、バックアップ以外の出力へ渡さないことを静的テストで確認する。`src/test/java/dev/nytweetdeck/account/AccountStoreTest.java`、`WebAccountVerifierTest.java`、`frontend/src/components/login-dialog.test.tsx`を行動の参照にする。
- AQUOS実機確認観点: X公式画面でパスワード、2要素認証、Passkey、Captchaを入力してアプリへ戻る。ログイン中に回転、アプリ切替、画面ロック、通信切替を行う。2アカウントを追加・切替・再起動し、別アカウントのポストや設定が混ざらないこと、戻る操作で認証状態が失われないことを確認する。

### A-03 メインメニュー、追加項目、公式Web遷移（3%）

- 観測可能な完了条件: 既定順を「ポスト作成、検索、ホーム、通知、ダイレクトメッセージ、トレンド」とする。追加可能項目「フォローする、チャット、Grok、プレミアム、プロフィール、コミュニティ、クリエイタースタジオ、ビジネス、広告、スペースを作成」を重複なく追加・削除できる。内部機能は対応画面を開き、公式Web項目は公式URLをAndroidの外部ブラウザ/Custom Tabで開いてアプリへ戻れる。
- 自動テスト観点: 既定順、全16項目の追加/削除、重複防止、compose/search/home/notification/message/trend/following/profileのルーティング、外部URLのAndroid IntentをCompose UI/Unitテストで確認する。表示文言に依存しないsemantic identifierを使う。
- AQUOS実機確認観点: 縦画面では全項目へ少ない操作で到達でき、項目が画面外へ隠れた場合もスクロールできることを確認する。横画面ではレール/ドロワーの位置、長押しとタップの競合、外部ページから戻った後の選択カラムを確認する。

### A-04 カラムの作成、削除、並べ替え、切替（4%）

- 観測可能な完了条件: 大きな追加導線またはカラム追加導線から「おすすめ、フォロー中、検索、通知、履歴、ユーザー、リスト、メッセージ、トレンド」の全9種を選べる。ユーザー/検索/リストは対象入力または候補選択を経て追加できる。カラムにタイトルと削除ボタンを表示し、必要数を追加・削除できる。投稿カラムごとに「トップ／最新」を選び、選択を保持できる。Androidでは長押しからドラッグして順序を変更し、スマートフォンでは1カラムを読みやすく表示し、複数カラムを切替できる。横画面/タブレットでは幅が許す範囲で複数カラムを同時表示する。
- 自動テスト観点: 9種追加、対象必須/不正入力、候補選択、カラム削除、順序変更、複数カラムの選択/スワイプ、レイアウト保存をCompose UIテストで確認する。リスト候補のmine/suggested/searchの重複排除は `frontend/src/components/add-column-dialog.test.tsx` と `model/list-directory.test.ts` を参照する。
- AQUOS実機確認観点: 縦画面でカラム本体を縦スクロールしているときに意図せず並べ替えが始まらないこと、横スワイプでカラム切替ができること、横画面でカラム間に重なり/横スクロール不能がないことを確認する。キーボード表示中の対象入力と追加ボタンも確認する。

### A-05 レイアウト永続化、版移行、競合、復旧（4%）

- 観測可能な完了条件: カラム、メニュー順、表示言語、投稿の翻訳先言語、テーマ、アクティブアカウント、返信並び順、カラムのトップ／最新順、表示設定、タイムライン自動更新、動画画質、トレンド検索履歴を変更すると自動保存され、アプリ再起動・再選択後に同じ状態になる。旧レイアウト版1〜8を現行形式へ明示移行する。保存中断・破損・欠落時は直前バックアップまたは既定値へ安全に復旧し、最新設定を失わない。並行更新では古い状態が新しい状態を無言で上書きせず、再試行または競合表示を行う。
- 自動テスト観点: Repositoryの原子的置換、backup復旧、破損/欠落、版1〜8移行、同一設定の無駄な再保存抑止、並行リビジョン競合、保存応答喪失後の重複適用防止をテストする。`frontend/src/model/layout.test.ts`、`shared-layout.test.ts`、`use-shared-layout.test.tsx`、`src/test/java/dev/nytweetdeck/settings/LayoutSettingsStoreTest.java`を基準にする。
- AQUOS実機確認観点: 設定変更直後のホームボタン/アプリ切替/force-stop/再起動、端末回転、空き容量が少ない状態を確認する。アプリ更新前後で設定が残り、復旧時に空のデッキへ勝手に戻らないことを確認する。

### A-06 設定JSONのインポート・エクスポート（2%）

- 観測可能な完了条件: メニュー、カラム、表示設定、返信並び順、トレンド検索履歴をバージョン付きJSONとしてエクスポートし、Androidのファイル共有/保存導線から取得できる。インポート時は形式、版、日時、全設定値、ファイルサイズを検証し、現在選択中アカウントを維持する。認証情報、保存済みアカウント、選択中アカウントIDをJSONに含めない。成功・失敗を利用者が判別できる。
- 自動テスト観点: 正常なラウンドトリップ、アカウントID除外、未知版、壊れたJSON、型不正、上限超過、インポート後のアクティブアカウント維持をテストする。`frontend/src/model/layout-transfer.test.ts` と `app.test.tsx` の期待値をAndroid契約テストへ移植する。
- AQUOS実機確認観点: Files/共有シートからJSONを選ぶ、キャンセルする、壊れたファイルを選ぶ、別アプリへ共有する、戻る操作を行う。インポート中に設定画面が操作不能にならず、成功後にメニュー/カラム/見た目が反映されることを確認する。

### A-07 カラム共通の取得、ページング、更新、キャッシュ（5%）

- 観測可能な完了条件: ログイン中の各投稿カラムで最新ポストが上に表示され、トップ順を選んだ場合は検索ではXのランキング、その他では取得済み投稿のエンゲージメント順で表示し、下へ進むとcursorで古いポストを追加する。重複ポストを出さず、読み込み中/空/失敗の各状態と再試行を表示する。表示済みカラムは再検証時に新着を先頭へ追加し、読んでいるポストの位置を維持し、新着件数と最大5人の作者アイコンを示す。設定で定期的なタイムライン自動更新を停止・再開できる。最上部からのPull-to-refreshは1ジェスチャー1回だけ実行し、中間位置の引き下げや横操作では誤更新しない。非表示時に更新を続けず、復帰時に同期する。
- 自動テスト観点: cursor追加・重複排除・日時降順、読み込み/timeout/再試行、キャッシュ即時表示、先頭再検証、viewport anchor維持、新着バナー、可視性、Pull-to-refresh閾値と多重起動抑止をfake clock/scrollテストで確認する。`timeline-column.test.tsx`、`timeline-cache.test.ts`、`fetch-with-timeout.test.ts`を参照する。
- AQUOS実機確認観点: 低速/切断/Wi-Fi・モバイル切替、最上部と中間位置での引き下げ、長時間スクロール、回転中の位置維持、新着バナーのタップ、アプリ切替からの復帰を確認する。200件相当の表示でスクロールが引っ掛からず、更新時に読んでいるカードが飛ばないことを確認する。

### A-08 おすすめ、フォロー中、検索、履歴、ユーザー、リスト（6%）

- 観測可能な完了条件: おすすめ（For You）、フォロー中、検索（入力語句のLatest）、履歴（保存済みポスト）、ユーザー（`@`ユーザー名を解決）、リスト（自分のリスト/候補/検索結果）をアクティブアカウント単位で取得・表示する。ユーザー/リスト対象を別アカウントへ混ぜない。リスト候補は名前、所有者、説明、件数を表示し、選択すると対象リストの時系列カラムを開く。
- 自動テスト観点: 6種のquery目的、アカウントID/target/cursor/languageの引き渡し、ユーザー名解決、リストscope mine/suggested/search、パーサーの作者/件数/重複排除/不正応答を契約テストする。`TimelineQueryFactoryTest.java`、`TimelineResponseParserTest.java`、`ListDirectory*Test.java`、`UserProfileServiceTest.java`を行動の根拠にする。
- AQUOS実機確認観点: 6種を順に追加して切り替え、別アカウントへ変更後に再取得する。日本語・長い検索語・`@`入力、候補ゼロ、対象不存在、ネットワーク失敗からの再試行を確認する。

### A-09 通知、フォロー通知ユーザー一覧（4%）

- 観測可能な完了条件: 通知カラムにいいね、リポスト、返信、フォロー、コミュニティノート、その他の通知を種別アイコンと文面で表示する。対象ポストがある通知はNyTD内のポスト詳細へ、集約フォロー通知は関係ユーザー一覧へ遷移し、ユーザー選択で内部プロフィールを開く。通知と関連ポストはcursorで追加でき、最上部更新、空/失敗/再試行を備える。
- 自動テスト観点: 通知分類、対象ポストID/ノートID、画像URLの安全化、集約actorの重複排除、通知とポストの混在、フォロー一覧→プロフィール遷移をテストする。`NotificationResponseParserTest.java`、`notifications-column.test.tsx`、`follow-notification-users-dialog.tsx`を基準にする。
- AQUOS実機確認観点: 通知項目のタップ領域、長い文面、複数アバター、対象ポスト詳細からの戻る、フォロー一覧からプロフィールへ進む/戻る、スクロール末尾の追加読み込みを確認する。通知がない/通信に失敗した場合に再試行ボタンが見えることを確認する。

### A-10 ダイレクトメッセージ受信箱（3%）

- 観測可能な完了条件: 認証済みアカウントのDM受信箱を新しい順に表示し、送信者名、`@ユーザー名`、アバター、本文、時刻を表示する。cursorで過去のメッセージを追加し、Live DM更新時に受信箱を再同期する。受信箱は閲覧機能として成立し、現行NyTDにない送信・編集・リアクションを未実装のまま表示しない。
- 自動テスト観点: Web受信箱のentries/users正規化、新しい順、送信者欠落、cursor、Live DMイベント、切断/再試行をテストする。`DirectMessageResponseParserTest.java`、`direct-message-column.test.tsx`、`LivePipeline*Test.java`を参照する。
- AQUOS実機確認観点: 長文、複数人/グループ由来の表示、アバター欠落、最下部追加、アカウント切替、ネットワーク断→復帰、画面回転を確認する。受信箱の縦スクロールがカラム/ナビゲーションの横操作を奪わないことを確認する。

### A-11 トレンド、絞り込み、検索履歴（2%）

- 観測可能な完了条件: Explore由来のトレンド名、順位、説明、ドメイン文脈を表示し、cursorで追加する。入力語句で名前/説明/文脈を取得済みデータから絞り込み、追加API通信を発生させない。トレンドをタップするとその語句の検索カラムを追加する。Enterで確定した語句は重複を除く直近20件として保存・復元でき、クリアと空結果を表示する。
- 自動テスト観点: トレンド正規化/cursor、安全なURLフォールバック、クライアント側絞り込み、Enter/clear、大小文字を無視した履歴重複排除と上限20をテストする。`TrendResponseParserTest.java`、`trends-column.test.tsx`、`layout.test.ts`を参照する。
- AQUOS実機確認観点: 日本語/英語の入力、IMEでEnter、長い語句、候補選択、クリア、空結果、トレンドから検索カラム追加、縦横回転後の入力値保持を確認する。
